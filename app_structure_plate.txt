PART 1 — DATA ARCHITECTURE (SINGLE SOURCE OF TRUTH)
================================================================================

CANONICAL MODEL
---------------
branches
  └── classes
        └── sections
              └── section_subject_teacher (allocation: who teaches what)
subjects (master catalog: name, code, branch_id ONLY)
  └── class_subject (curriculum: which subjects each class offers)
  └── teacher_subjects (capability: subjects teacher is qualified to teach)
teacher_profiles.class_teacher_of (ONLY source for class teacher)
time_tables (weekly schedule only — validated against section_subject_teacher)

REMOVED / DEPRECATED COLUMNS (migrations 2026_06_08_*)
------------------------------------------------------
- subjects.class_id, subjects.section_id
- classes.teacher_id
- teacher_profiles.is_class_teacher
- teacher_subjects.class_id, teacher_subjects.is_class_teacher
- section_subject_teacher.class_id (derive via sections.class_id)

ADDED
-----
- branch_id on teacher_subjects, class_subject, section_subject_teacher
- app_notifications table (per-user notifications)

ASSIGNMENT SERVICE (app/Services/Academic/AssignmentService.php)
----------------------------------------------------------------
assignClassCurriculum()      → class_subject pivot
assignTeacherCapabilities()  → teacher_subjects pivot
assignSectionTeachers()      → section_subject_teacher (PRIMARY allocation)
assignClassTeacher()         → teacher_profiles.class_teacher_of
getTeacherScope()            → (class_id, section_id, subject_id) tuples
validateTimetableSlot()      → enforces allocation before timetable save

ACADEMIC SETUP FLOW (Admin)
---------------------------
1. Classes & Sections
2. Subject Catalog (master list)
3. Class Curriculum (class_subject)
4. Teacher Capabilities (teacher_subjects)
5. Section Teacher Allocation (section_subject_teacher) ← PRIMARY
6. Class Teacher (teacher_profiles.class_teacher_of)
7. Timetable (validates against step 5)
Route hub: admin.academic.setup
